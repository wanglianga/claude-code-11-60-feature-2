# 应急调度合成数据演练台

面向应急调度培训团队的**本地**合成数据生成与质量验证工具：从去标识化历史事件中生成可重复的练习数据，保留报警、派车、到场、结案之间的有效关系，不把原始个案复制到培训环境。

- 技术栈：React 18 + TypeScript + Vite；IndexedDB（Dexie）本地持久化；WebWorker 执行生成与核验
- 纯前端本地应用，**不调用任何外部服务**；无后端，故不提供 Swagger/OpenAPI
- 随题样例：`public/samples/emerg-2025-09/`（r1 首批登记 + r2 迟到源修订），覆盖并发派车、多级转运、罕见组合、跨午夜任务

## 功能地图

| 模块 | 说明 |
| --- | --- |
| 来源批次 | 登记批次：实算每个文件 SHA-256 并与 batch.json 声明比对；登记字段含义与修订号；批次内容按修订不可变，运行中的任务继续引用启动快照，迟到修订另起运行 |
| 关系规则 | 事件/派遣/资源/到场/结案的引用与先后约束；车辆占用按实际任务区间 `[派遣, 到场+周转]` 以绝对毫秒核验，**跨午夜不算日期倒序**；审批后不可原地改，再编辑自动派生新版本 |
| 生成方案 | 记录要保留的全局事件类型、时长分布与随机种子；乐观锁保存——两管理员并发保存同一方案时展示冲突字段；审批门禁拒绝未审/宽松规则 |
| 生成运行 | 固定来源与规则快照，输出全新标识的多表演练包；两条路线可选（约束驱动条件采样 / 分布学习+批量抽样+约束筛选），均满足同一关系规则 |
| 质量核验 | 约定的总体统计比对、引用完整性、资源占用、时间可行性；直接标识扫描、源记录近乎复制、导出字段独特组合；两路线同一核验 |
| 条件化偏差 | 对已完成运行按 **严重度 × 所需资源类别 × 并发负荷** 交叉比较源样本与合成包的到场时长与未及时响应率；预先锁定成熟口径；两条路线（独立分层 / 层级部分汇聚）并给出支持数、区间、尾部差异与“不可判定”范围；只读，不改数据 |
| 发布清单 | 由输入计算产生，可回查来源批次（修订+文件哈希）、规则、运行参数（方法/种子/规模）与核验结果，支持重新校验与导出 |

## 测试账号

本工具为纯本地应用，**无后端账号体系、无需登录**。页面左下角的操作员选择（管理员A / 管理员B）仅作为本地身份标记，用于演示审批签名与「两人并发保存同一方案」的冲突处理。

## 操作与验证路径（建议顺序）

1. **来源批次** → 点「加载随题样例 r1」：查看文件哈希实算结果、字段含义表；点「源数据体检」可见 r1 中 2 条缺失到场、3 条结案时间异常（迟到修订素材）。
2. **关系规则** → 「新建标准规则」→ 检查约束后「审批」。
3. **生成方案** → 「新建方案」自动从批次学习分布 → 选择生成路线（界面有两路线适用条件说明）→ 保存 →「批准」。可尝试把容差改到系统边界外（如类型占比容差 50pp）再批准，会被门禁拒绝；引用未审批规则同样被拒绝。
4. **生成运行** → 对方案「开始生成」（WebWorker 进度条）→「查看输出」预览五张表、导出 CSV。
5. **质量核验** → 对运行执行核验：总体统计比对、引用完整性、资源占用（跨午夜安全）、时间可行性、直接标识、近乎复制、独特组合，附风险提示与核验范围声明。
6. **条件化偏差** → 对同一运行「开始分析」：以该运行的来源修订为比较对象，预先锁定成熟窗口与分层条件，输出按 严重度 / 资源类别 / 并发负荷 / 严重度×资源类别 / 严重度×并发负荷 的逐格报告。查看每格的支持数（源/合成可用数、因结案未成熟或缺到场被排除数）、到场均值与分位差（p50/p90/p95，附确定性 bootstrap 区间）、分布距离 TVD、未及时响应率差（Newcombe 区间）、R2 汇聚偏差与收缩权重/τ² 敏感性、两路线一致性；页面顶部单列“高负荷被显著压低”和“高负荷不可判定”两组结论，底部列出全部“无法稳定估计的范围”，报告可导出 JSON。
7. **发布清单** → 生成清单后「回查视图」看 批次→规则→运行→核验 全链路哈希，「重新校验」逐项重算比对，可导出 JSON。
8. **迟到源修订演示** → 回到「来源批次」加载 r2：r1 标记「已被取代」；已完成的运行仍引用 r1 快照（运行记录中有提示），新运行默认使用 r2。对旧运行做条件化分析时，报告会提示“该批次已登记更新修订，本报告固定在运行快照上比较”。
9. **并发冲突演示** → 两名操作员先后编辑同一方案：先保存者成功，后保存者看到冲突字段对照表（你的值 vs 库中当前值），可选择覆盖或放弃重载。

## 复现说明

同一「方案 + 批次快照 + 规则版本 + 种子」必然产生同一演练包：发布清单记录了全部输入哈希（批次文件、规则、方案参数、输出表、核验报告），在「发布清单 → 重新校验」可逐项重算比对。

## 风险核验范围声明

基础风险核验只覆盖：①导出字段中的直接标识（模式匹配 + 源值逐字比对）；②与源记录的近乎复制；③已声明字段组合的独特性（k 阈值）。**不宣称能抵御针对特定目标的定制攻击**、背景知识链接或组合推断；演练包应按内部受控资料管理。

## 条件化偏差分析：方法与解释边界

总体报警量与平均到场时间接近源样本，并不表示在压力条件下也接近。本模块以「同一来源修订 → 由其生成的运行包」为**唯一**比较对象，并**预先锁定**下列口径（报告内回显、写入哈希）：

- **成熟口径**：观察截止取该数据集内最晚结案时间（按绝对时间，跨午夜安全）；报警距截止不足成熟窗口（默认取 `max(480 分钟, 规则集全程上限)`）的事件视为尚未成熟；无有效结案（结案早于末次到场）或结案缺失的事件同样排除。**结案未成熟的事件绝不当作及时响应**；成熟但缺到场记录的事件也不进入及时响应口径，分别单独计数。
- **分层条件**：严重度（优先级）、所需资源类别（由规则的能力映射推出）、并发负荷（报警时刻同刻仍占用的其他车辆数 + 已报警未派遣的其他事件数）。并发分桶只用**源样本**取值分布预先锁定，避免用合成数据反推阈值；交叉维度为 严重度×资源类别、严重度×并发负荷。
- **指标**：首程到场时长（报警→首程到场）的均值、中位、p90、p95、分布距离 TVD，以及“未及时响应率”（到场时长 > 阈值，默认 15 分钟）。

两条路线在**相同条件下**评估源与合成的业务指标失真：

| 路线 | 做法 | 优点 | 代价 |
| --- | --- | --- | --- |
| R1 独立分层 | 每个足量分层各自计算 TVD 与分位差 | 直观，不借用其他群体信息 | 交叉维度增多后小格样本稀少 |
| R2 层级部分汇聚 | 以资源类别为组，在相关事件类型间做 DerSimonian-Laird 随机效应汇聚得到组先验，再按方差把各格对数均值差向组先验收缩 | 降低稀疏格波动 | 依赖“同类事件类型可共享偏差结构”的假设；τ² 越大越不可信 |

报告同时给出 R2 的 **τ² 敏感性范围**（乘数 0.5/1/2 及原始↔汇聚插值）、**收缩权重**、**借用类型数**与**未汇聚原始支持度**，并要求两路线方向一致才判定“存在偏差”；方向相反且均显著时列入“无法稳定估计/需谨慎解释”。

**解释边界**：任一分层支持不足时标为“稀疏·仅 R2 参考”或“不可判定”，单列于“无法稳定估计的范围”，**绝不并入总体掩盖**。高负荷（P1 或并发最高档）下若支持不足，单列“高负荷不可判定”，供培训负责人明确“不能据此认为压力下仍有余量”。源样本与合成包的事件定义（事件类型）或地理边界（行政区）版本不一致、或运行快照文件哈希与登记不一致时，**拒绝直接比较**。分析全程只读，不修改任何生成数据、方案或批次；报告可由“导出 JSON”留档并含内容哈希。

## 目录结构

```
src/domain/     纯领域逻辑（生成器A/B、约束、统计、隐私、核验、清单、冲突、条件化偏差条件统计）
src/services/   编排层（批次登记、运行/核验/条件化分析 Worker 编排、清单、导出）
src/workers/    WebWorker 入口（生成 / 核验 / 条件化分析）
src/pages/      八个页面
src/db/         Dexie（IndexedDB）schema
public/samples/ 随题样例（r1 + r2 迟到修订，含 batch.json 声明哈希与 fields.json 字段字典）
scripts/gen-samples.mjs  样例再生成脚本（确定性，node scripts/gen-samples.mjs）
tests/          vitest 测试
```
